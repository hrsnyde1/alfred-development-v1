# Disposable network acceptance protocol (future OS authorization only)

This protocol has **not** run. It uses no Photon credentials or provider connection. The reviewer must authorize a disposable public TCP/443 listener, a local/private sentinel listener, probe-only cgroup exceptions, the uniquely named UID nft table and targeted cleanup. Do not alter Personal Alfred's unit or firewall rules. The `photon-reply-probe@.service` unit is `Type=oneshot` with `TimeoutStartSec=15s`; its Node TCP deadline is 3 seconds. A timeout, `ECONNREFUSED` or an unreachable route never independently proves a filter.

## Common evidence

For each trial record: test UID, exact effective unit properties (`systemctl show photon-reply-probe@<trial>.service -p User -p RootDirectory -p IPAddressDeny -p IPAddressAllow -p TimeoutStartUSec -p Result`), independent listener address/port and successful control-identity connection, test result/exit code, test-table counters before and after, and the Personal Alfred unit's active state and existing connection state before and after. Use only numeric disposable addresses; do not log SDK data, credentials or host message contents. The root-owned `/etc/photon-reply-test/probe.env` contains only `EXPECT`, `HOST`, `PORT`, all reviewed and numeric; set mode `0400`. Verify the probe process has the test UID and no credentials or production mounts. Use `systemd-analyze verify` and inspect the effective drop-in before each trial.

## Separate trials and PASS criteria

| Trial | Preparation | Required independent evidence | PASS |
|---|---|---|---|
| Cgroup deny | No test nft table; probe `IPAddressDeny=any`, no allow. Confirm a disposable local and a private-network listener are reachable from a control identity. | Effective cgroup IP properties, BPF attachment where inspectable, probe exit and listener controls. | Test UID receives `EACCES` or `EPERM` for each, while control identity connects. Timeout/refusal/inability to inspect effective policy is inconclusive. |
| UID nft deny | Add a reviewed **probe-only** `IPAddressAllow=` for one disposable public listener. Install only `inet alfred_photon_reply_test` using the transactional procedure, with that address absent from its allow set. Confirm the listener from a control identity. | Exact test UID match, nft drop counter increment during one isolated probe, listener control success, no other UID match or other-table change. | Test connection fails **and** counter increments for that UID, while control identity connects. A timeout alone is inconclusive. |
| Approved allow | Use the same probe-only cgroup exception and a separately reviewed temporary test-table policy allowing only that disposable public IP/TCP 443. | nft accept counter increment, probe `PASS: allow connected`, and listener-side connection record for the test UID; verify no other address or port is allowed. | All three observations agree. Remove temporary exception and policy before any Photon test. Actual provider connection remains a separately authorized live gate. |
| Local/private deny | Restore provider-only policy and remove probe-only cgroup exception. Confirm both listeners independently. | Cgroup denied result for local/private targets and no unexpected nft accept; inspect policy after restoration. | `EACCES`/`EPERM` with listener controls; a timeout alone fails to establish cause. |
| Personal Alfred unaffected | Before and after each table/drop-in change, inspect its unit state and existing Photon connection without changing it. | Same active service, expected connection remains; no non-test UID match, no other nft table changed. | All unchanged. Any uncertainty stops acceptance. |

The nft drop trial can time out by design. Its **composite** evidence is an incremented UID-specific nft drop counter, independently reachable listener, effective probe cgroup exception and unchanged control-identity success. Never label the socket timeout itself as a PASS. For cgroup denial, nft must be absent to isolate the mechanism. If the host lacks cgroup IP enforcement or nft counters, mark acceptance **inconclusive** and stop. Do not loosen the production or Personal Alfred firewall.

## Cleanup and interruption

Stop only probe instances; verify no test-UID process remains before replacing the test table. Remove the probe-only drop-in and run `systemctl daemon-reload`; verify effective `IPAddressAllow` has returned to provider-only (or none). Use the targeted test-table hash and deletion procedure in `OPERATOR_CANDIDATE.md`; never flush rulesets. On interruption, preserve policy/counter evidence, inventory the exact table and drop-in, and complete only their independently reviewed targeted rollback. No `os-acceptance.ok` marker may be created on an incomplete or inconclusive trial.
